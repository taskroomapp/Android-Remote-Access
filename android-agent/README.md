# Android agent

> **Development/prototype component.** The Android application requests access to highly sensitive device capabilities. Build, install, enroll, and operate it only on an organization-owned test device or an emulator with the informed, revocable consent of the person using the device. It is not a background-stealth application: it runs as a visible foreground service.

The full project status and known release blockers are in [../docs/SECURITY_AND_PRIVACY.md](../docs/SECURITY_AND_PRIVACY.md). For emulator testing, use [../docs/LOCAL_TESTING.md](../docs/LOCAL_TESTING.md).

## Build

Open `android-agent/` in Android Studio, or use the Gradle wrapper:

```bash
cd android-agent
./gradlew assembleDebug
./gradlew installDebug        # requires a connected emulator/device
```

On Windows, use `gradlew.bat` (or `./gradlew` from PowerShell if the wrapper is executable).

`installDebug` fails with `No connected devices!` when no emulator/device is visible to ADB. Before installing:

1. Boot an AVD (Android Studio Device Manager, or `emulator -avd <name>`).
2. Confirm the device is online:

   ```powershell
   # If adb is not on PATH, use the SDK copy:
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices -l
   ```

   Expect a line like `emulator-5554   device`. If the list is empty, or the state is `offline`/`unauthorized`, fix that before retrying `installDebug`.
3. Launch the installed app from the emulator, or:

   ```powershell
   adb shell am start -n com.remoteagent/.ui.MainActivity
   ```

The project currently has no instrumented-test suite. A successful APK build does not validate runtime permissions, network reachability, or integration with the Go service.

## App lifecycle

```text
MainActivity
  ├─ displays agent UUID, server URL, server device ID, and connection state
  ├─ requests declared runtime permissions and optional Usage Access
  ├─ logs in and registers the device when “Register device with server” is used
  └─ starts/stops AgentService

AgentService (foreground dataSync service)
  ├─ builds WebSocket URL from stored server URL + server device ID
  ├─ connects using OkHttp
  ├─ sends enrollment metadata after connection
  ├─ sends heartbeat every 30 seconds
  ├─ retries a disconnected service after 5 seconds
  └─ dispatches server DeviceCommand messages to CommandHandler

CommandHandler
  ├─ checks runtime permission where applicable
  ├─ invokes implemented Android/platform helpers
  └─ returns success/failure bytes to AgentService
```

`AgentService` uses `START_STICKY` and shows a foreground notification with the text “Remote agent active / Connected to management server.” Android may still stop or restrict the service under platform power-management rules.

## Enrollment and connection

The app uses two UUIDs:

- **Agent UUID**: generated locally and stored with `KeyStoreIdentity` / preferences.
- **Server device ID**: generated by `POST /api/v1/devices`; required for the WebSocket path and stored in `AgentPreferences`.
- **CKX1 keys**: long-term X25519 + Ed25519; public keys enrolled on the server.

Interactive enrollment uses administrator credentials entered in the app:

1. The app requests `POST /api/v1/auth/login`.
2. It registers agent UUID, hardware metadata, and CKX1 public keys / fingerprint through `POST /api/v1/devices`.
3. It stores the returned **server device ID**.
4. It starts a foreground service connected to `/ws/devices/{server-device-id}`.

For an Android emulator on a Windows host, run the repository’s ADB reverse helper and use:

```text
http://127.0.0.1:8443
```

The `127.0.0.1` address is the emulator loopback after ADB reverse. Details are in [Local testing](../docs/LOCAL_TESTING.md). Cleartext traffic is permitted only for `10.0.2.2`, `localhost`, and `127.0.0.1` by `network_security_config.xml`; this is for development only.

## Device WebSocket protocol

- Endpoint: `ws://` or `wss://<host>:8443/ws/devices/<server-device-id>` depending on the configured base URL.
- Header: `X-Device-UUID: <agent-uuid>` identifies the connection candidate; it is not authentication by itself.
- Handshake (plaintext bootstrap): server `key_offer` → agent verifies pinned server fingerprint → agent `key_exchange` (Ed25519 signature over CKX1 transcript) → server verifies enrolled public keys → `session_ready`.
- After handshake: all application traffic is CKX1 `{ "type": "enc", "nonce", "ciphertext", "seq", "dir", "txn", … }` with ChaCha20-Poly1305.
- Frame AAD: length-prefixed `CKX1-FRAME-V1` + session/device/dir/seq/txn.

- Inner enrollment: `type: "enrollment"` with agent/device metadata (sent encrypted after `session_ready`).
- Heartbeat: every 30 seconds, inner `type: "heartbeat"` with battery level (encrypted).
- Command result: inner `type: "response"`, transaction ID, command type, status, and base64-encoded bytes (or an error), wrapped in `enc`.

The server sends sealed `DeviceCommand` JSON (`transaction_id`, `command_type`, `payload`, `timeout_seconds`, `issued_at`) inside `enc` frames.

Full contract: [Session encryption](../docs/SESSION_ENCRYPTION.md). Encryption coverage: [Encryption coverage](../docs/ENCRYPTION.md).

## Current command compatibility

The server allowlist and the Android `DeviceCommand.CommandType` enum declare more commands than the handler actually registers. The table below is the source-of-truth status for `CommandHandler.registerDefaultExecutors()`.

| Command family | Agent status | Current behavior / constraints |
| --- | --- | --- |
| File list / directory | Implemented | Uses Java `File` on the supplied path; returns immediate child metadata. Android scoped storage and filesystem permissions still limit visibility. |
| One-shot file read | Implemented | Reads a supplied file path; rejects directories and files larger than 10 MiB. |
| Chunked file read | Implemented | Reads a bounded byte range; max requested chunk is 512 KiB. Used by server-side stream aggregation. |
| File deletion | Implemented | Calls Java `File.delete()` when the path exists and is writable. No server-side allowlisted-root policy exists. |
| File write / rename / move / upload / download | Declared, not registered | Handler returns `Unknown command type`. |
| Contacts | Implemented | Requires `READ_CONTACTS`; returns contact name, phone, and email fields available through Android providers. |
| Call logs | Implemented | Requires `READ_CALL_LOG`; default limit is 100. |
| SMS messages | Implemented | Requires `READ_SMS`; supports handler payload filtering fields, subject to Android/role restrictions. |
| Foreground app | Implemented/conditional | Requires the user to grant Usage Access in Android settings; returns the most recently used app from usage stats, not a guaranteed real-time foreground process. |
| Installed apps | Implemented | Lists installed application metadata; package visibility may affect results. |
| Browser history | Declared, not registered | Returns `Unknown command type`; Android does not grant a general browser-history API. |
| Device information | Implemented | Returns Android ID, build/model, battery, and data-directory storage statistics. |
| One-time location | Implemented/conditional | Requires fine location permission and an enabled provider. Tries a fresh single update and may fall back to last known location. |
| Camera still | Implemented/conditional | Requires `CAMERA`; invokes `CameraCaptureHelper` for a JPEG. No continuous stream handler is registered. |
| Camera stream / stop | Declared, not registered | Returns `Unknown command type`. |
| Timed audio record | Implemented/conditional | Requires `RECORD_AUDIO`; records Ogg bytes for duration (default 60 seconds). |
| Audio start/stop | Implemented/conditional | `mic_start` with `mode: "start"` or duration 0 starts helper state; `mic_stop` returns a JSON wrapper containing Base64 audio. Server action aliases are not fully equivalent. |
| Microphone stream | Declared, not registered | Returns `Unknown command type`. |
| Heartbeat / enroll / disconnect | Protocol/system declarations | Not registered as handler commands; heartbeat and enrollment are emitted by `AgentService`. |

## Permissions

The manifest declares networking, foreground-service, storage/media, camera, microphone, contacts, call-log, SMS, location, notification, boot, package-query, and usage-stats related permissions. `MainActivity` currently asks for many runtime permissions in a single operational flow:

- camera,
- record audio,
- contacts,
- call logs,
- SMS,
- fine/coarse location,
- notifications on Android 13+, and
- media/storage read permission appropriate to the Android version.

It also directs the user to Usage Access settings when foreground-app detection is unavailable.

This broad request model is not suitable for a consent-centered release. Production work must change it to contextual, feature-by-feature permission requests with clear purpose, opt-out/revocation, and no command execution until an explicit relevant grant exists.

## Transport and certificate status

The agent stores CKX1 identity keys via `KeyStoreIdentity` and configures OkHttp with an SSL context when the URL starts with `wss://`. Application-layer authentication uses pinned server fingerprint verification plus an Ed25519-signed CKX1 handshake transcript that the server checks against enrolled public keys before `session_ready`. The server can request a TLS client certificate, but mutual TLS is not required-and-verified at the WebSocket upgrade. Do **not** claim connection-time mTLS for this source tree.

## Known integration limitations

- A single command response is base64 encoded by the agent, decoded by the server hub, and later exposed through mixed JSON/binary code paths. Content type and response shape are not uniformly modeled.
- Android permission availability, OEM restrictions, scoped storage, role restrictions for SMS/call data, and location provider state can all cause a supported command to fail.
- The agent does not expose a general browser-history implementation despite a declared command enum value.
- The app's broad runtime permission request, automatic reconnect, and boot receiver declaration require a privacy/security redesign before release.
- The server currently does not enforce a device-authentication boundary for a WebSocket path.

For stack-level limitations, read [Architecture](../docs/ARCHITECTURE.md) and [Security and privacy](../docs/SECURITY_AND_PRIVACY.md).
