# API reference

> **Current-source reference.** API endpoints below are extracted from `server/internal/api/handlers.go`, `file_stream.go`, and `mirrors.go`. A registered route is not necessarily a complete feature. Status labels are included to prevent clients from relying on placeholder behavior.
>
> Requests must be made only against systems and Android devices for which the operator has explicit authorization. See [Security and privacy](SECURITY_AND_PRIVACY.md).

Base URL in local development: `http://localhost:8443`  
Versioned API prefix: `/api/v1`

## Conventions

### Authentication

Protected HTTP routes use:

```http
Authorization: Bearer <access-token>
```

Access tokens are HS256 JWTs. The code creates 15-minute access tokens and 7-day refresh tokens. Authentication resolves the administrator from PostgreSQL on each protected request.

### Content type and errors

JSON requests should send `Content-Type: application/json`. Success payloads are JSON unless a download/stream endpoint is used.

The standard error shape is:

```json
{
  "error": "human-readable message",
  "code": "MACHINE_READABLE_CODE"
}
```

Common server-generated codes include `UNAUTHORIZED`, `FORBIDDEN`, `INVALID_REQUEST`, `INVALID_ID`, `INVALID_COMMAND`, `MISSING_PARAM`, `NOT_FOUND`, and `DB_ERROR`.

### Command envelope

`POST /commands` accepts the current generic command envelope:

```json
{
  "device_id": "server-device-uuid",
  "command_type": "file_list",
  "payload": "{\"path\":\"/storage/emulated/0\"}",
  "timeout_seconds": 60,
  "priority": 5
}
```

`payload` is a **string containing JSON**, not a JSON object, in the server model. The web panel converts an object to a string before submission. A submission returns a transaction ID and either an immediate result or `queued` status. Clients may then query `/commands/{transaction_id}`.

The server validates a fixed command-type allowlist, but the Android agent only implements a subset. Refer to the compatibility matrix in [android-agent/README.md](../android-agent/README.md) before designing a client around a command type.

## Device registry routes

All routes in this section require a Bearer token.

| Method | Route | Status | Notes |
| --- | --- | --- | --- |
| `GET` | `/api/v1/devices` | Implemented | Lists PostgreSQL device rows and merges currently connected hub clients. Requires role-derived `device:status` or `device:command`. |
| `POST` | `/api/v1/devices` | Partial | Creates/re-enrolls a device record. It is authenticated, but the handler does not independently enforce `device:enroll`. |
| `GET` | `/api/v1/devices/{id}` | Implemented | Returns a registry row and derives current `status` from the hub. |
| `DELETE` | `/api/v1/devices/{id}` | Implemented | Requires `device:revoke`; deletes DB row and closes an active hub connection. |
| `GET` | `/api/v1/devices/{id}/status` | Implemented | Returns hub online state, DB battery/last check-in, and Redis sorted-set queue count. |

Enrollment body:

```json
{
  "device_uuid": "agent-local-uuid",
  "friendly_name": "Android device",
  "owner": "field-agent",
  "os_version": "14",
  "hardware_model": "Manufacturer Model",
  "certificate_hash": "fingerprint-or-pending"
}
```

Successful enrollment returns a distinct `device_id` generated by the server. Do not substitute the agent-local UUID for this ID when constructing device WebSocket paths.

## Command and file routes

| Method | Route | Status | Notes |
| --- | --- | --- | --- |
| `POST` | `/api/v1/commands` | Implemented/partial | Generic command dispatch. Requires role-derived `device:command`; may return `queued` if device is offline. Agent support varies by command. |
| `GET` | `/api/v1/commands/{transaction_id}` | Implemented | Reads in-memory result, then Redis helper, then audit row. Audit trigger conflict may leave persisted status stale. |
| `POST` | `/api/v1/commands/{transaction_id}/cancel` | Stub | Returns a message that cancellation is not implemented. |
| `GET` | `/api/v1/files/list?device_id={id}&path={path}` | Partial | Uses the generic dispatcher for file listing. |
| `GET` | `/api/v1/files/read?device_id={id}&path={path}` | Partial | Uses the generic dispatcher for a one-shot read. Agent caps this path at 10 MiB. |
| `GET` | `/api/v1/files/stream?device_id={id}&path={path}` | Implemented/partial | Aggregates `file_read_chunk` responses (32 KiB chunks) and accepts a starting `Range: bytes=N-` value. No server storage-root/canonical-path policy exists. |
| `DELETE` | `/api/v1/files/delete?device_id={id}&path={path}` | Partial | Dispatches agent deletion if role has `file:*`; use only after a separately reviewed authorization decision. |
| `GET` | `/api/v1/files/download/{file_id}` | Implemented | Decrypts `media_files.encrypted_data` (CK01) and returns plaintext bytes to an authenticated admin. Fails closed if the encryptor is missing or decrypt fails. |

Command response shape:

```json
{
  "transaction_id": "uuid",
  "status": "success | failed | queued | pending | timeout | cancelled",
  "queued": false,
  "created_at": "timestamp",
  "data": "optional response text",
  "error": "optional error text"
}
```

The direct file endpoints return their response data as a string. Binary agent replies are base64-decoded by the Go WebSocket hub, then represented as a string in JSON-oriented command handlers; client code must not assume an explicit MIME type.

### Action payloads currently parsed by the server

```json

{ "action": "snapshot", "camera": "back" }

// microphone action
{ "action": "start", "duration": 60 }

// location action

```

The generic `/commands` endpoint is the panel's primary path. Do not assume the action aliases are behaviorally equivalent until they have integration tests.

## Roles and permissions: current behavior

The `PermissionChecker` derives permissions from the administrator **role** using a fixed Go map. It does not use the individual `permissions` array stored in the `administrators` table. Current roles are:

| Role | Role-derived capability groups |
| --- | --- |
| `super_admin` | Device enrollment/revocation/commands, all file/contact/call/SMS/camera/microphone/location groups, audit, administration. |
| `admin` | Device commands, read/list file operations, contacts/calls, snapshot/record/location, audit. |
| `operator` | Device status, file list, contacts, calls. |

The precise permission strings reside in `server/internal/security/security.go`. Role-only evaluation and missing per-device authorization are release blockers for a multi-tenant or production design.

## Admin CKX1 REST channel

After JWT login, the control panel must complete CKX1 before calling protected APIs:

| Method | Path | Role |
| --- | --- | --- |
| `POST` | `/api/v1/auth/ckx1/offer` | JWT; returns server X25519/Ed25519 public keys + nonce |
| `POST` | `/api/v1/auth/ckx1/exchange` | JWT; client signs transcript; response includes `ckx1_session` |

Protected JSON APIs require header `X-CKX1-Session: {ckx1_session}`. Request/response bodies use `type=enc` CKX1 frames (ChaCha20-Poly1305). Binary download/stream/export paths require the header but are not JSON-wrapped.

## WebSocket endpoints

| Endpoint | Authentication | Current role |
| --- | --- | --- |
| `/ws/devices/{server_device_id}` | CKX1 handshake required before session readiness | `key_offer` / `key_exchange` / `session_ready`, then `type=enc` commands and replies. See [Session encryption](SESSION_ENCRYPTION.md). |
| `/ws/admin?token={access_token}&ckx1={ckx1_session}` | Access JWT + CKX1 session token | Presence broadcasts sealed with the admin CKX1 session |

### Device WebSocket session messages

Bootstrap messages are plaintext by design and authenticated by Ed25519 + enrolled X25519/Ed25519 public keys. After `session_ready`, all application messages use CKX1 `type=enc` frames (X25519-derived directional keys + ChaCha20-Poly1305). TLS remains mandatory. Application-layer AEAD does not replace TLS.

The URL and `X-Device-UUID` identify a connection candidate only. Commands are rejected until `session_ready`.

| Outer `type` | Direction | Body |
| --- | --- | --- |
| `key_offer` | server → device | `protocol=CKX1`, `version`, `session_id`, `server_x25519_public_key`, `server_ed25519_public_key`, `server_fingerprint`, `server_nonce`, `algorithm=X25519-HKDF-SHA256-CHACHA20-POLY1305` |
| `key_exchange` | device → server | `session_id`, `device_id`, raw base64 public keys, `device_nonce`, Ed25519 `signature` over the CKX1 handshake transcript |
| `session_ready` | server → device | `session_id`, `protocol`, `version`, `algorithm` |
| `enc` | both | `session_id`, `seq`, `dir`, `txn`, `nonce`, `ciphertext` — AAD is length-prefixed `CKX1-FRAME-V1` fields |

Commands fail with `device session not established` if dispatched before the handshake completes.

The WebSocket upgrader's origin check presently returns `true` for every origin. This API must sit only in an isolated local development environment until a production authentication and origin-validation design is implemented.
